# Lumora — AI Habit Execution & Mood Telemetry

**Live:** https://lumora-ten-psi.vercel.app

A full-stack personal performance, habit-tracking, and AI journaling web application built with **Next.js (App Router)**, **Supabase (PostgreSQL + Google OAuth + RLS)**, **Google Gemini AI**, and **Recharts**.

Designed with a high-density **Compact Bento Telemetry** interface (`Plus Jakarta Sans` + `JetBrains Mono` with tabular numerals), Lumora turns daily workouts, task completion, and written reflections into a deterministic `0–100` daily performance score and multi-week habit-to-mood correlation analytics.

---

## Core Engineering Highlights

* **Hybrid Daily Scoring Engine:** Combines objective task execution (`50%`) with Gemini AI reflection analysis (`50%`) into a bounded `0–100` composite score.
* **Deterministic LLM Pipeline:** Uses the `@google/genai` SDK with strict **Structured JSON Outputs (`responseSchema`)** and low temperature (`0.3`) to guarantee schema-valid mood classification, sentiment polarity (`-1.0` to `+1.0`), and coaching insights.
* **Zero-Latency Optimistic UI:** Implements React `useOptimistic` and `useTransition` on daily gym, work, and habit checklists for sub-100ms client state transitions backed by Next.js Server Actions.
* **Database-Level Multi-Tenant Security:** Enforces PostgreSQL **Row-Level Security (RLS)** (`auth.uid() = user_id`) across all tables alongside an automated `PL/pgSQL` trigger for profile provisioning on Google OAuth sign-up.
* **Habit-to-Mood Correlation Analytics:** Joins 30-day journal sentiment records against completed `GYM` checklist dates via $O(1)$ set lookups to quantify emotional polarity lift on workout days vs. rest days.
* **Zero-Cost Infrastructure & CI Keep-Alive:** Runs on Vercel Hobby, Supabase Free Tier, and Google AI Studio Free Tier, with a scheduled GitHub Actions workflow pinging Supabase every 5 days to prevent inactivity pauses.

## Hybrid Daily Scoring Formula

Each day's performance is evaluated deterministically when a journal entry is submitted or updated:

$$\text{Daily Score} = \text{round}\Big((0.5 \times \text{Checklist Completion \%}) + (0.5 \times \text{AI Reflection Score})\Big)$$

1. **Checklist Completion %:** Ratio of completed tasks across `GYM`, `WORK`, and `HABIT` categories for the current ISO date.
2. **AI Reflection Score (`0–100`):** Generated by Gemini `2.5-flash` using a strict JSON schema alongside `mood_label`, `sentiment_score` (`-1.0` to `+1.0`), and a concise `ai_insight`.
3. **Idempotent Upserts:** Journal submissions use `ON CONFLICT (user_id, entry_date)` so entries can be refined and re-scored throughout the day without duplicating rows or inflating streaks.

## Database Schema (PostgreSQL)

Three normalized tables protected by Row-Level Security:

* **`profiles`**: `id` (UUID, PK), `email`, `full_name`, `avatar_url`, `current_streak`, `updated_at`
* **`journal_entries`**: `id` (UUID, PK), `user_id` (FK), `entry_date` (Unique per user), `content`, `mood_label`, `sentiment_score`, `ai_insight`, `final_daily_score`
* **`daily_checklist`**: `id` (UUID, PK), `user_id` (FK), `task_date`, `title`, `category` (`GYM` | `WORK` | `HABIT`), `is_completed`, `points`

## Local Setup

### 1. Clone & Install Dependencies

```bash
git clone [https://github.com/](https://github.com/)<your-username>/<your-repo-name>.git
cd <your-repo-name>
pnpm install
```

### 2. Configure Environment Variables

Create a `.env.local` file in the root directory:

```env
NEXT_PUBLIC_SUPABASE_URL=your_supabase_project_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key
GEMINI_API_KEY=your_google_ai_studio_api_key
```

### 3. Provision Supabase Database & Google OAuth

1. Run the SQL schema, RLS policies, and `handle_new_user()` trigger inside the **Supabase SQL Editor**.
2. Enable **Google** under **Authentication → Providers** and configure your OAuth 2.0 Client ID in **Google Cloud Console** with `http://localhost:3000/auth/callback` authorized.

### 4. Start Development Server

```bash
pnpm dev
```

Open `http://localhost:3000` to sign in and start logging telemetry.

## Deployment (Vercel)

1. Push the repository to GitHub and import it into **Vercel**.
2. Add `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and `GEMINI_API_KEY` under **Project Settings → Environment Variables**.
3. Update **Site URL** and **Redirect URLs** in **Supabase Authentication** (`https://<your-domain>.vercel.app/auth/callback`) and add your production origin in **Google Cloud Console**.
4. Add `SUPABASE_URL` and `SUPABASE_ANON_KEY` to **GitHub Repository Secrets** to enable the automated keep-alive workflow.
